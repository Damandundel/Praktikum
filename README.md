# Praktikum

**Система за управление на ученически стажове и практическо обучение** – дипломен проект
(ЧПГДН „СофтУни Будител“, специалност „Приложно програмиране“).

Уеб системата ще обхваща целия процес: от кандидатстването за стажантска позиция до
отчитането и оценяването на изпълнените дейности.

## Състояние на проекта

Хранилището съдържа структурата на решението (проекти, папки и файлове) за контролната
проверка от Етап 1. Файловете с изходен код са създадени, но още са празни – кодът се добавя
постепенно по етапите. В `docs/` е въведението на документацията.

## Роли

| Роля | Какво прави |
|------|-------------|
| Администратор | Управлява потребители, роли, периоди и системни настройки |
| Координатор (учител) | Периоди, организации, критерии, одобрява кандидатури, назначава наставник и график, справки |
| Работодател | Профил на организацията и публикуване на позиции |
| Наставник | Потвърждава записите в дневника, оценява по критерии |
| Ученик | Разглежда позиции, кандидатства, води дневник, вижда график и оценки |

## Технологии

C# / ASP.NET Core MVC (.NET 8) · Entity Framework Core (Code First) · MS SQL Server ·
ASP.NET Core Identity (cookie автентикация) · HTML5 / CSS3 / JavaScript ·
xUnit, coverlet, ReportGenerator · GitHub Actions

## Архитектура

```
Praktikum.sln
├── src/
│   ├── Praktikum.Web/          # MVC: Controllers, Views, wwwroot
│   ├── Praktikum.Services/     # Бизнес логика
│   ├── Praktikum.Data/         # DbContext, конфигурации, миграции, seeding, хранилища
│   ├── Praktikum.Data.Models/  # Entities и enum-и
│   └── Praktikum.Common/       # Константи и общи класове
├── docs/                       # Документация
└── .github/workflows/ci.yml    # CI (ръчно стартиране)
```

Поток на заявката: `Controller → Service → Repository → DbContext`.
Зависимости между проектите: `Web → Services → Data → Data.Models`, а `Common` се ползва от всички слоеве.

## CI

Работният процес `.github/workflows/ci.yml` се стартира ръчно (`workflow_dispatch`), защото
приложението още няма изходен код и не може да бъде изградено. Автоматичното стартиране при
push и pull request се включва, когато кодът бъде добавен.

## Сигурност на конфигурацията

В хранилището няма пароли, ключове и connection strings. За разработка се ползват
User Secrets, а за продукция – променливи на средата на хостинга.
